# {{COMPANY}} SOP Template

## Purpose of This Format

{{COMPANY}} SOPs are designed to be:
- **Human-friendly**: clear section hierarchy, numbered steps, explicit decision points, plain language
- **AI-consumable**: structured YAML frontmatter, consistent field names, machine-readable metadata, parseable decision logic

Every SOP generated by `/sop-gen` must follow this exact template.

---

## Template

```markdown
---
sop_id: "sop-{team-abbreviation}-{slug}-v{version}"
title: "{Process Name}"
owner: "{Full Name or Role}"
team: "{Team Name}"
version: "{X.Y}"
status: "draft"  # draft | active | deprecated
last_updated: "{YYYY-MM-DD}"
reviewed_by: ""
tools_required:
  - "{Tool 1}"
  - "{Tool 2}"
triggers:
  - "{What initiates this process}"
frequency: "{daily | weekly | ad-hoc | on-trigger}"
estimated_time: "{N minutes / hours}"
related_sops:
  - "{sop-id-of-related-process}"
tags:
  - "{relevant-tag}"
---

# {Process Name}

## Purpose
One sentence: why this process exists and what problem it solves for the team or system.

## Scope
Who runs this process, under what conditions, and what it explicitly does and does not cover.

## Prerequisites
- [ ] Access to {tool}
- [ ] {Required input or data}
- [ ] {Any prior process that must be completed first}

## Steps

### Step 1: {Action Title}
**Owner**: {Role}
**Tool**: {`~~crm` (HubSpot) / `~~enrichment` / `~~knowledge base` (Notion) / etc.}
**Input**: {What you need before starting this step}

{Clear, imperative description of what to do. One idea per step. Use sub-bullets for detail.}

**Output**: {What exists after this step is complete}

---

### Step 2: {Action Title}
**Owner**: {Role}
**Tool**: {Tool}
**Input**: {Output from Step 1, or other input}

{Description of action.}

> **Decision point**: If {condition A}, proceed to Step 3. If {condition B}, go to Step 5 (Edge Cases).

**Output**: {What exists after this step}

---

### Step N: {Final Action}
**Owner**: {Role}
**Tool**: {Tool}
**Input**: {Prior output}

{Description.}

**Output**: {Final deliverable or state change}

---

## Quality Checks
Run these after the final step to confirm the process completed correctly:
- [ ] {Verification item 1}
- [ ] {Verification item 2}

## Escalation and Edge Cases

| Scenario | What to Do |
|----------|------------|
| {Edge case or failure mode} | {Action to take} |
| {Data missing or incomplete} | {Fallback or escalation path} |

## Notes
{Any contextual information, background, or caveats that don't fit the steps above.}

## Changelog

| Version | Date | Author | Summary |
|---------|------|--------|---------|
| 1.0 | {YYYY-MM-DD} | {Name} | Initial version |
```

## Field Reference

| Field | Required | Notes |
|-------|----------|-------|
| `sop_id` | Yes | Format: `sop-{team}-{slug}-v{X.Y}`. Example: `sop-mops-lead-routing-v1.0` |
| `title` | Yes | Title-case process name |
| `owner` | Yes | Name or role of process owner |
| `team` | Yes | Which team owns and runs this |
| `version` | Yes | Start at `1.0`; increment minor for small updates, major for full rewrites |
| `status` | Yes | `draft` until reviewed and approved |
| `tools_required` | Yes | List all tools a person needs access to |
| `triggers` | Yes | What event or condition starts this process |
| `frequency` | Yes | How often it runs |
| `related_sops` | No | Link to upstream/downstream processes |

## SOP ID Naming Convention

`sop-{team}-{process-slug}-v{version}`

Team abbreviations:
- `mops` — Marketing Operations
- `sales` — Sales / RevOps
- `mktg` — Marketing
- `cs` — Customer Success
- `ops` — General Operations
